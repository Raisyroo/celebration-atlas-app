# Celebration Atlas Constellations Architecture

## Purpose

Atlas Constellations transform event markers from ordinary map pins into meaningful discovery objects.

A constellation is a relationship between celebrations.

The goal is to make the map feel like a living atlas:

* events are stars
* important events glow brighter
* related events connect into trails
* dense areas become starfields
* seasonal activity pulses over time

## Core Principle

The marker is not just a pin.

It is a signal:

* what kind of event this is
* how important it is
* when it happens
* how confident the data is
* whether it belongs to a trail
* whether it is worth exploring now

## Marker Meaning

### Star

A normal event.

Used for:

* standard local events
* basic atlas listings
* ordinary discoveries

### Bright Star

A major or highly relevant event.

Used for:

* flagship events
* high-confidence events
* events with rich media
* events with full experience pages
* events featured by the Atlas

### Pulsing Star

A timely or active event.

Used for:

* happening soon
* happening now
* newly updated
* seasonal feature
* live/field scout coverage

### Dim Star

A lower-priority or low-coverage event.

Used for:

* basic listings
* low-confidence records
* events without dates
* events not currently in season

### Hidden Star

A discoverable event not shown by default.

Used for:

* hidden gems
* search-revealed results
* zoom-revealed results
* dense-map decluttering

### Cluster Glow

A density signal.

Used for:

* regions with many events
* cities with many discoveries
* seasonal hotspots
* category concentrations

## Constellation Meaning

A constellation is a thematic or geographic relationship between events.

Examples:

* County Fair Trail
* Great Lakes Fireworks
* Harvest & Apple Path
* Winter Lights
* Haunted Michigan
* Summer Music Arc
* Waterfront Celebrations
* Historic Parades
* Queen Pageant Trail
* Small-Town Labor Day Traditions
* Balloon Glow Circuit
* Food Festival Trail
* Art Fair Weekend
* Fairground Memories

A constellation can be:

* curated manually
* generated by AI and reviewed
* source-backed
* seasonal
* regional
* category-based
* historical
* practical/travel-based

## Star Intensity Rules

Star appearance should come from event metadata.

Possible drivers:

* coverageLevel
* featured status
* hiddenGem status
* confidenceScore
* sourceStatus
* season relevance
* date proximity
* media richness
* current activity
* user saved status
* user attendance history
* AI recommendation score

Suggested hierarchy:

* coverage level 1: dim star
* coverage level 2: normal star
* coverage level 3: bright star
* coverage level 4: pulsing star when current
* coverage level 5: flagship constellation node

## Relationship Types

Constellations may be created from:

### Category Relationships

Events of the same type.

Examples:

* county fairs
* fireworks
* food festivals
* art fairs
* music festivals

### Seasonal Relationships

Events that define a season.

Examples:

* summer fair circuit
* fall harvest trail
* winter lights
* spring blooms

### Geographic Relationships

Events in a region.

Examples:

* Thumb celebrations
* Great Lakes shoreline events
* Upper Peninsula summer trail
* Detroit metro holiday lights

### Historical Relationships

Events connected by history or tradition.

Examples:

* oldest festivals
* queen pageant traditions
* historic parades
* lost festivals
* Civil War / heritage celebrations

### Practical Travel Relationships

Events that work as a trip.

Examples:

* one-day nearby route
* weekend festival loop

* waterfront weekend

### Cultural Relationships

Events that share a cultural theme.

Examples:

* foodways
* immigrant traditions
* harvest rituals
* music scenes
* local legends

## Interaction Rules

Initial interaction:

* hovering/tapping a star reveals event preview
* tapping a constellation reveals its trail summary
* search highlights matching stars
* filters reveal or dim relevant stars

Later interaction:

* save constellation
* collect trail artifacts
* mark attended events
* view constellation story
* ask AI about trail
* generate a route

Avoid:

* showing every constellation at once
* creating visual spaghetti
* using lines that overpower the map
* making markers look like generic app pins

## Scaling Rules

### Small event count

Show individual stars and a few labels.

### Hundreds of events

Use clusters, brighter featured stars, and search-revealed stars.

### Thousands of events

Use:

* density glows
* region-level clusters
* search/list/filter
* constellation overlays
* zoom-based reveal
* seasonal feature layers

Never show thousands of equally bright stars at once.

## AI-Agent Compatibility

Agents may suggest:

* constellation membership
* star intensity
* event relationships
* seasonal trails
* regional clusters
* hidden gems
* route-worthy groups
* source confidence

Agents must provide:

* reason for suggestion
* confidence score
* source references where possible
* review status

AI-generated constellations should be marked as:

* suggested
* reviewed
* published
* retired

## Source and Confidence Rules

Constellations should distinguish:

* verified relationship
* editorial/curated relationship
* AI-suggested relationship
* loose thematic grouping
* practical travel grouping

Do not present weak AI relationships as historical fact.

Examples:

* “County fairs in Southeast Michigan” can be algorithmic.
* “Events connected by a shared founder” needs sources.
* “Harvest traditions trail” may be editorial.
* “Best fireworks route” may be ranking/editorial plus sources.

## Visual Design Rules

Stars should feel:

* warm
* magical
* discoverable
* premium
* soft
* atmospheric

Avoid:

* generic map pins
* harsh neon
* cluttered labels
* dashboard markers
* overly bright white dots
* excessive animation

Preferred star style:

* warm ivory/gold center
* soft amber halo
* subtle pulse for active/current events
* faint glow for clusters
* delicate constellation lines
* reduced opacity for inactive layers

## Responsive Behavior

### Phone Portrait

* few visible stars at once
* search and shortcuts guide discovery
* constellation trails appear as focused overlays or cards
* avoid clutter

### Phone Landscape

* simplify starfield
* keep discovery/list reachable
* avoid large overlays

### Tablet

* allow more constellation context
* show trail summaries near map

### Desktop

* full constellation exploration
* map plus discovery panel
* optional trail inspector

## Implementation Priorities

1. Keep current event markers working.
2. Do not replace map markers immediately.
3. Add constellation concepts as data/documentation first.
4. Later add marker presentation types.
5. Later convert visual circles into star markers.
6. Later add constellation overlays.
7. Later add AI-suggested trails with review status.

## Final Direction

Atlas Constellations make Celebration Atlas feel alive.

The real map tells users where an event is.
The star tells users it is worth noticing.
The constellation tells users it belongs to a bigger story.
